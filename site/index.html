the shape

GitHub stays canonical. Your machine does the work.

Git, issues and pull requests stay exactly where they are. The laptop becomes the executor: it mirrors the repos, runs the pipelines, hosts the agent surface, and keeps the logs. Nothing is written back to GitHub unless you push it yourself.

one private network

Five devices. One tailnet. Zero open ports.

Every service binds to loopback and is published by tailscale serve, so it is reachable from your own devices over HTTPS and from nowhere else. No router port forwards, no public certificate, no funnel.

what's inside

Five parts. One config file.

Everything lands in /opt/oma-stack. Everything is configured in /etc/oma-stack/host.env. Re-running the installer is safe: it keeps every secret it finds and every choice you made.

tracker

Forgejo

Your tracker, your mirror, your CI server. Repos mirrored one-way from GitHub every 15 minutes; issues snapshotted read-only every 30.

execution

Two runners

A Forgejo runner for your own pipelines, and a GitHub self-hosted runner so public repos keep their CI alive while the account is billing-locked.

surface

OpenBot

The CopilotKit agent surface in a single container — app, API, browser tools and an embedded database, reachable from any of your devices.

agents

Agent bridge

Exposes your local agents over AG-UI so OpenBot can call them, and runs the handoff queue: a case goes in, an answer comes out.

ops

oma CLI

One command for the whole thing: oma doctor tells you what's broken and what to do, oma status shows the lot in one screen.

safety

Approvals

The bridge never merges, never deploys, never touches a credential. It writes proposals; a human accepts them. Every handoff is logged.

the rules

Boring where it matters.

01

Hot data stays on the internal SSD. Database, repositories, CI logs, artifacts, mirror cache, Docker data-root. The 4 TB USB disk holds dated backups and nothing else.

02

The USB disk is optional. Unplug it and CI, the mirror and the tracker keep running — the healthcheck says WARN, never FAIL.

03

One direction only. GitHub → Forgejo. The mirror reads; it never pushes, never opens a PR, never closes an issue.

04

Nothing is exposed publicly. Loopback binds, tailscale serve, exact-match agent allowlist, single-user mode on by default.

05

Re-running is safe. Every step is idempotent, every existing secret is kept, GitHub is never touched by the uninstaller.

install

Two ways in.

Both end in the same place: /opt/oma-stack installed and /etc/oma-stack/host.env waiting for you.

one line
$curl -fsSL https://raw.githubusercontent.com/MartinMayday/oma-stack/main/bootstrap.sh | sudo bash

Clones the kit to /opt/oma-stack and runs the installer.

clone
$git clone https://github.com/MartinMayday/oma-stack.git && cd oma-stack && sudo ./bootstrap.sh

Runs the installer from your own checkout, so you can change it first.

Then, two keys

The only things you must supply: the CopilotKit Intelligence key and one model key. The installer generates every other secret and tells you exactly what is still missing.

$sudo nano /etc/oma-stack/openbot.env

Then, look

One command tells you the state of the whole stack and what needs you.

$oma doctor
questions

The obvious ones.

Why not just use GitHub Actions?

Because on this account it cannot start. Hosted jobs sit there forever and private-repo workflows never even register — a billing lock, not a configuration problem. oma-stack does not work around the lock; it moves the execution to hardware you control while leaving your git workflow untouched.

Is the mirror going to fight with my branches?

No. It clones one-way from GitHub and force-pushes only the mirror's own branches. Your working copies on Forgejo are yours to push to; the mirror never touches them.

What happens if the USB disk is not plugged in?

The backup timer skips itself and the healthcheck reports WARN. Nothing else notices — the tracker, the mirror and CI all live on the internal SSD by design.

Can the agents merge things on their own?

No, and that is enforced, not promised. The bridge can run an agent and write its answer to the outbox; it never merges, deploys, or changes a credential. Every handoff is recorded in the audit log and waits for a human.

Do I need the tailnet to use oma-stack?

No. Tailscale is how your other four devices reach the box, and it is optional. Without it everything still runs on localhost and the LAN exactly as before.
